# Android 接口与行为

核对日期：2026-11-01。服务端完整协议以 [CustodySim 原生接入规格](https://github.com/PDSB001/CustodySim/blob/master/docs/android-client.md) 为权威；本页记录 **当前 App 的实现与边界**，避免复制一份必然漂移的 API 清单。

## 1. 当前关键约定

| 能力       | App 实现                                                          |
| ---------- | ----------------------------------------------------------------- |
| 客户端代际 | `X-CustodySim-Client: android-app/2`（服务端校验 `^android-app/\d+$`） |
| 业务鉴权   | `Authorization: Bearer <token>`，不使用浏览器 Cookie              |
| 刷新       | 401 后单飞刷新，保存轮换后的 refreshToken，仅重试一次             |
| MFA        | 受信任设备头 `<deviceId>.<token>`，值由服务端下发                 |
| 聊天图片   | 代际 2 用 `imageUrl` 认证取字节，兼容旧服务端的内联数据           |
| 实时       | 自实现 Engine.IO v4 / Socket.IO v5，跑在 OkHttp WebSocket 上      |
| 正文共享   | `X-CustodySim-Reader-Delivery: shared-v1`，按响应头校验阅读身份   |
| 原生阅读   | EPUB/DOCX 用 Episteme，TXT 用 StaticLayout，PDF 用 PdfRenderer    |
| 协议阅读   | 《用户协议》《隐私政策》随包离线渲染，不联网                      |

`/api/mobile/server-info` 里的 `nativeProtocol` 区间是**服务器检测契约**，与聊天图片的客户端代际不是同一个字段，不要混用；前者决定能否连接，后者决定图片与正文的传输形态。

## 2. 身份与安全边界

- 所有请求由 `ApiClient` 统一添加原生头、Bearer 与取消支持；写请求缺少原生头会被服务端按不可信来源 403 拒绝。该头不参与鉴权，伪造它拿不到权限。
- 令牌存于应用私有存储，优先 Android Keystore AES-GCM；在 Keystore 不可用的环境降级为软件 AES-GCM，并以 `k:` / `s:` 前缀区分解密路径。不要绕开这层直接写明文文件。
- 401 才触发刷新；刷新失败才视为登录失效。403 表示权限或来源问题，**不能**当作未登录直接清凭据；5xx 保留凭据并提示重试。写失败时先确认服务端是否已经成功，避免重复提交。
- 退出登录调用服务端接口使该账号所有设备的会话失效；切换服务器只清本机旧凭据，不主动踢掉其他设备。
- App 没有修改密码页面；首次改密与安全设置走同一服务的 Web 页面。
- 令牌、可信设备凭据、异常响应正文、推送注册日志都不写入可公开的日志。

## 3. 服务器检测与切换

- 只接受 `https://` 根地址；`ServerEndpoint.normalize` 负责去尾斜杠与校验，非法输入不发请求。
- 检测调用 `/api/mobile/server-info`，核对 `nativeProtocol` 区间；失败或区间不兼容时不切换，也不覆盖用户已保存的选择。
- 切换成功后停止旧容器、旧会话与待上传队列，清掉本机旧凭据，要求重新登录；编译期默认端点永远不覆盖用户保存的运行期选择。

## 4. 功能入口与页面契约

| 页面         | 关键约束                                                                 |
| ------------ | ------------------------------------------------------------------------ |
| 首页概览     | 打卡、任务、通知、计分板入口；摘要单行化，不为说明文案留空行             |
| 考核计分板   | 周次、排名、三项来源、明细与人工登记；姓名脱敏与明细权限完全按 `/api/scores` 响应 |
| 通知         | 合并公示、详情展开、未读筛选、搜索、分页、批量已读，提交携带版本号       |
| 聊天         | 前台 WebSocket + 后台厂商通道；图片走认证下载，不拼接公开直链            |
| 社区 / 档案  | 自愿公开的档案内容；删除与可见范围由服务端裁决                           |
| 图书馆       | 元数据、正文、插图分层缓存，见[阅读与缓存](reader-cache.md)              |
| 我的         | 服务器设置、通知与消息、后台运行、协议阅读、开源许可、版本号             |

计分板的规则文案必须来自响应里的 `policy`，与服务端实际计分、图书馆阅读设置同源；旧服务端没有返回规则时显示“暂不可用”，不在客户端编造分值。

## 5. 阅读与媒体传输契约

- 开书先请求 `GET /api/library/{id}/document?metadata=1`，在线校验会话、访问范围、`readerKey` 与 `revision`，之后才允许使用本地副本。
- 没有正文缓存时携带 `shared-v1`，服务端或 EdgeOne 可返回公共正文；响应必须同时给出 `X-CustodySim-Reader-Delivery: shared-v1`、`X-CustodySim-Reader-Key` 与 `X-CustodySim-Media-Revision`，三者与本次请求一致才落盘。
- gzip 由 OkHttp 透明协商；落盘前按实际文件头判断是否解压，保存完整个人文档。旧服务端的个人 JSON 形态保持兼容读取。
- 5xx、传输异常、gzip/JSON 损坏或共享身份不一致，只尝试一次 `/document-origin` 恢复；401/403/404 与主动取消不恢复。

## 6. 实时聊天（Socket.IO）

单个会话一条连接，只处理“加入会话 + 下行事件”，不引入官方 socket.io 客户端（避免额外依赖与 R8 反射入口）。

| 阶段     | 报文                                                                 |
| -------- | -------------------------------------------------------------------- |
| 握手     | `GET {realtimeUrl}/socket.io/?EIO=4&transport=websocket`，服务端先发 `0{...}` |
| 鉴权     | 客户端发 `40{"token":"<jwt>"}`，令牌由服务端实时令牌接口换取          |
| 心跳     | 服务端发 Engine.IO `2`，客户端必须回 `3`；不使用 OkHttp 自带 ping    |
| 加入会话 | `42<ackId>["conversation:join","<conversationId>"]`，成功回 `43<ackId>[{"ok":true}]` |
| 下行事件 | `message.created`、`message.recalled`、`conversation.created`         |
| 令牌续期 | 实时令牌只对一个会话有效、约 300 秒过期；提前 60 秒换新并重连（最短 30 秒） |

实现要点：连接失败不抛异常，状态置为 `Failed` 并由上层轮询兜底；重复 `join` 同一会话是无操作；`leave` 只退出会话、不断开信道；未知事件忽略而不崩溃。服务端到期强制断连属于正常路径，不要当异常上报。

## 7. 定位与通知的客户端边界

- 定位分成一次性打卡定位与后台周期上报两套开关，互不联动；5 / 10 分钟走前台服务，≥15 分钟走 WorkManager 兜底，断网的点留在有界队列。详见[权限与定位](permissions.md)。
- 通知默认关闭；开启后才注册友盟、FCM 与华为通道，关闭时解绑服务端设备并过滤迟到推送。详见[App 通知与推送](push-notifications.md)。

## 8. 协议变更流程

1. 先改服务端契约与兼容回归，再改 App 解析；确认旧版本客户端仍能运行主要路径。
2. 递增 `android-app/N` 只在传输形态真的变化时进行，不要只改数字不改解析。
3. 阅读位置、`readerKey`、`revision`、定位与计时字段属于跨端约定，改动必须双仓同步并在文档中写明。
4. 发布前按[开发与发布](android-development.md)在真实设备复验登录刷新、聊天重连、图片、阅读与定位授权。

## 9. 排障与验收

| 现象                     | 排查方向                                                       |
| ------------------------ | -------------------------------------------------------------- |
| 所有写请求 403           | 原生头缺失或被中间层剥掉；确认代际值与服务端校验正则           |
| 反复掉登录               | 刷新令牌并发使用导致轮换失效；检查是否真的单飞                 |
| 聊天只显示轮询结果       | WebSocket 握手、令牌过期或服务端实时进程未启动，看状态流转     |
| 图片空白                 | `imageUrl` 认证下载失败或旧服务端内联形态未兼容                |
| 阅读卡在“正在校验”      | metadata 被拒（会话/范围/revision），不是缓存问题              |

编译与 JVM 测试通过不等于真机网络、后台与手势验收通过；历史路径与事故记录见[旧客户端规格](archive/android-client-legacy.md)。
